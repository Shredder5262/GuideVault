# GuideVault Home Assistant Connector

GuideVault 0.9.211 includes a bidirectional Home Assistant connector with content-type targeting for open commands.

## GuideVault settings

Open **Settings > Server > Integrations > Home Assistant** and configure:

- **Home Assistant URL**: use the Home Assistant base URL only, for example `http://homeassistant.local:8123`. Do not include `/api` or a dashboard path.
- **Long-Lived Access Token**: create this in Home Assistant under your user profile
- **Entity Prefix**: default `guidevault`
- **GuideVault Command Token**: generated by GuideVault; copy this into Home Assistant REST commands

## Published Home Assistant entities

GuideVault publishes these entities through the Home Assistant REST API:

- `sensor.guidevault_reader`
- `sensor.guidevault_current_item`
- `sensor.guidevault_page`
- `sensor.guidevault_library_items`

The reader sensors include attributes such as item id, item title, item kind, page, page count, progress percentage, zoom, display mode, and transition mode.

GuideVault can also fire a `guidevault_event` Home Assistant event when reader activity or commands occur.

## Command endpoint

Home Assistant can control the active GuideVault browser reader by posting to:

```text
POST http://GUIDEVAULT_HOST:5478/api/home-assistant/command
Authorization: Bearer GUIDEVAULT_COMMAND_TOKEN
Content-Type: application/json
```

Supported actions:

- `open` — accepts `itemId`, `itemTitle`, `query`, and optional `itemKind` / `kind` / `contentType` / `itemType` values such as `Manual`, `Strategy Guide`, or `Magazine`
- `open_manual`, `open_strategy_guide`, and `open_magazine` — aliases for `open` with the content type inferred
- `next_page`
- `previous_page`
- `first_page`
- `last_page`
- `set_page`
- `zoom_in`
- `zoom_out`
- `set_zoom`
- `set_display_mode`
- `toggle_overlay`
- `close_reader`
- `status`

## Example Home Assistant REST commands

```yaml
rest_command:
  guidevault_next_page:
    url: "http://GUIDEVAULT_HOST:5478/api/home-assistant/command"
    method: post
    headers:
      Authorization: "Bearer GUIDEVAULT_COMMAND_TOKEN"
      Content-Type: "application/json"
    payload: '{"action":"next_page"}'

  guidevault_previous_page:
    url: "http://GUIDEVAULT_HOST:5478/api/home-assistant/command"
    method: post
    headers:
      Authorization: "Bearer GUIDEVAULT_COMMAND_TOKEN"
      Content-Type: "application/json"
    payload: '{"action":"previous_page"}'

  guidevault_open_item:
    url: "http://GUIDEVAULT_HOST:5478/api/home-assistant/command"
    method: post
    headers:
      Authorization: "Bearer GUIDEVAULT_COMMAND_TOKEN"
      Content-Type: "application/json"
    payload: '{"action":"open","itemId":"{{ item_id }}"}'

  guidevault_open_by_title_and_type:
    url: "http://GUIDEVAULT_HOST:5478/api/home-assistant/command"
    method: post
    headers:
      Authorization: "Bearer GUIDEVAULT_COMMAND_TOKEN"
      Content-Type: "application/json"
    payload: >
      {
        "action": "open",
        "itemTitle": "{{ item_title }}",
        "itemKind": "{{ item_kind | default('') }}"
      }

  guidevault_set_page:
    url: "http://GUIDEVAULT_HOST:5478/api/home-assistant/command"
    method: post
    headers:
      Authorization: "Bearer GUIDEVAULT_COMMAND_TOKEN"
      Content-Type: "application/json"
    payload: '{"action":"set_page","page":{{ page | int }}}'

  guidevault_set_zoom:
    url: "http://GUIDEVAULT_HOST:5478/api/home-assistant/command"
    method: post
    headers:
      Authorization: "Bearer GUIDEVAULT_COMMAND_TOKEN"
      Content-Type: "application/json"
    payload: '{"action":"set_zoom","zoom":{{ zoom | int }}}'
```

## Opening a specific content type

When a title exists as a manual, strategy guide, and magazine reference, include `itemKind` so GuideVault opens the intended type:

```yaml
action: rest_command.guidevault_command
data:
  command_action: open
  item_title: "Super Mario 64"
  item_kind: "Strategy Guide"
```

Accepted content-type values include:

- `Manual`
- `Strategy Guide`
- `Magazine`

Aliases such as `manuals`, `guides`, `strategy`, and `magazines` are normalized by GuideVault. You can also use `command_action: open_manual`, `command_action: open_strategy_guide`, or `command_action: open_magazine`.

## Automation idea

```yaml
alias: GuideVault - notify when a guide opens
trigger:
  - platform: state
    entity_id: sensor.guidevault_reader
    to: "reading"
action:
  - service: persistent_notification.create
    data:
      title: "GuideVault"
      message: "Opened {{ state_attr('sensor.guidevault_reader', 'item_title') }}"
```
